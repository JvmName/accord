# Authorization matrix — (actor role, action, resource state) -> allow | deny
#
# Written by task 02b. Consumed by tasks 12 and 15.
# Executable form: server/test/characterization/authorization.test.js
#   (46 assertions, driven over real HTTP against a booted ApplicationServer;
#    it must pass UNCHANGED against the task-12 route middleware, which is the
#    parity proof task 15 needs before deleting lib/server/authorizer.js).
#
# DENY  = HTTP 401 with the exact envelope { data: null, status: 'unauthorized' }
# ALLOW = the request reached the action (asserted as a specific non-401 status)
#
# ACTORS
#   creator   created the mat, so mat.creator_id == creator (the "master")
#   judge     joined the mat with the ADMIN code -> mat judge, and match judge
#             once the match starts (Match#start copies mat.getJudges())
#   viewer    joined the mat with the VIEWER code
#   outsider  authenticated, but unrelated to the mat
#   anon      no x-api-token header at all
#
# This table is FIDELITY, not correctness. Rows marked [F-nn] pin behavior that
# is arguably wrong; see .ai/plans/server-ts/FINDINGS.md.
